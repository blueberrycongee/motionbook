# Deterministic clock motion

## What this implements

`motion.js` is an independently authored, dependency-free rigid-body approximation of the observed six-digit falling clock. It contains no copied application source, physics library, font asset, or trajectory table from Kitasenju Design.

Six separately simulated digits are created each second. Gravity acts on the first simulation step after creation, with no stationary presentation interval. A thin, invisible platform permits accumulation and front/back/side spills. Bodies have translational and rotational velocity, box inertia, quaternion orientation, and frictional collision impulses. The pile at the start is generated by running the same simulation before source time zero.

This is **not Bullet/Ammo**, an identification of the creator's current engine, or a pixel-identical reproduction. The recording is a reference for appearance and timing; its original random state and exact physics are unknown.

## Public API

Browser: load `motion.js`, then use `ClockMotion`.

Node: `const ClockMotion = require('./motion.js')`.

```js
const simulation = ClockMotion.createSimulation({
  seed: 4262026,
  startTime: '12:39:42',
  preRoll: 8,
  spawnPhase: -1.2,
  gravity: 1300
});
const state = simulation.stateAt(18); // state.text === '124000'
```

`ClockMotion.stateAt(seconds, options)` is a convenience equivalent with a four-simulation cache. Reuse a factory instance during playback for predictable memory/performance. `ClockMotion.DEFAULTS` and `ClockMotion.VERSION` are exported. A factory also provides `cacheInfo()` and `reset()`. The convenience cache provides `ClockMotion.cacheInfo()` and `clearCache()`.

### Input contract

- `seconds`: a finite number from zero through `maxSeconds`, inclusive. Default maximum is 120 seconds; an explicit maximum may be 1–600 seconds. Negative, non-finite, nonnumeric, and out-of-range time values throw.
- `seed`: uint32 or a string of at most 128 UTF-16 code units. There is no `Math.random`, current date, wall clock, or frame-time dependency.
- `startTime`: strict 24-hour `HH:MM:SS`, or integer seconds since midnight from 0 through 86399. Time wraps at midnight.
- `preRoll`: integer 0–30. Row `-preRoll` is the first simulated row. It is born at `-preRoll + spawnPhase`, so a negative phase adds that much physical initialization time before zero. Default 8.
- `spawnPhase`: finite number -3 through 0. Row n, labeled `startTime+n`, is born at source second `n+spawnPhase`. Default -1.2 is an estimated timing alignment, not a source constant. A future-labeled row can already exist above the visible frame.
- `fixedStep`: exactly `1/120` (default) or `1/60`. Changing it intentionally changes trajectories.
- Spawning is fixed at one six-digit row per second. `spawnInterval` currently accepts only 1.
- All numeric tunables are range-checked. Unknown option keys throw. Do not pass renderer settings into motion options.
- `useGlyphBounds`: boolean, default true. Box dimensions and center offsets come from this deliverable's OFL-derived/customized glyph meshes. The shoulder-style unfooted “1” has width 93.10546875 at cap scale 210.
- `bodyWidth`: default 140. With glyph boxes enabled, `bodyWidth/140` is a horizontal collision-box multiplier. It does not rescale visible meshes. With `useGlyphBounds:false`, it is the literal common box width, regardless of digit.
- `capHeight`: visible mesh scale and collision-bound scale, default 210. Glyph overshoot can make actual bounding height slightly larger.
- `thickness`: total, centered extrusion thickness in world units, default 50.
- Main available tunables also include `spawnY`, `gravity`, `slotSpacing`, `positionJitter`, `depthJitter`, `rotationJitter`, `mass`, `restitution`, `friction`, platform dimensions/Y, linear/angular damping, solver iterations, and lifecycle/cache limits. See `DEFAULTS` and the validation table for their exact accepted ranges.

### Output contract

`stateAt` returns a fresh object:

- `time`: requested seconds
- `text`: six-character HHMMSS clock reading, based on `floor(seconds)`
- `clock`: parsed hours/minutes/seconds, plus `spawnedText` and `latestRow`
- `bodies`: independent rendering poses
- `platform`: invisible platform position and full dimensions
- `stats`: body count, total spawned/removed, total solved contact pairs, fixed step
- `parameters`: frozen normalized options; `startTime` is normalized to numeric seconds since midnight

Each body provides:

- `id`, `digit` (string `'0'`–`'9'`), `row`, `slot`, `bornAt`, `age`
- `position`: world-space **mesh origin**, adjusted for the glyph box-center offset
- `physicsPosition`: world-space box center of mass
- `quaternion`: `[x,y,z,w]`, unit length
- `rotation`: equivalent Euler radians applying X, then Y, then Z
- `velocity`, `angularVelocity`: world-space center-of-mass linear/angular velocities
- `scale`: cap height; `thickness`: full world depth; `depth`: thickness/scale for the earlier geometry renderer
- `collider`: full box dimensions; `colliderLocalCenter`: local displacement of box center from mesh origin

Coordinates are right-handed, Y up, camera-facing front at positive Z. Quaternions are preferred over Euler angles for rendering and interpolation. IDs can be negative because pre-roll rows exist. Bodies are ordered by creation and keep stable IDs until removal. Caller mutation of returned body arrays cannot alter the underlying simulation.

## Historical baseline versus calibrated demonstration

The mechanical baseline is informed by the separately reviewed historical “Helvetica Clock 2” description: gravity 1300, glyph scale about 210, thickness 50, six slots 180 apart, box collision shapes, mass 300, restitution .2, friction .6, and a 1000×20×60 platform centered at Y=-100. The historical source is not verified as the exact 2026 recording. No historical program or asset is included or executed by this implementation.

The measured 2026 screen capture suggests slower visible descent at the fitted scale than a literal historical-default run. An evaluated demo preset is:

```js
{
  seed: 4262026,
  startTime: '12:39:42',
  capHeight: 220,
  spawnY: 1000,
  gravity: 850,
  spawnPhase: -1.34,
  maxBodies: 48
}
```

Pair camera/framing settings separately in the renderer. The scene configuration is authoritative for the delivered demo; this preset is an evaluated starting point. Global timing/scale fitting does not identify unique physical parameters.

## Numerical method and explicit approximations

- Fixed-step semi-implicit integration; normalized quaternion orientation integration
- 15-axis oriented-box separating-axis test, with a small face-axis preference to reduce unstable edge switching
- Clipped face contact manifolds, at most four contact points; closest support-edge contact for edge/edge collisions
- Sequential accumulated normal and two-tangent friction impulses, ten iterations by default, alternating pair traversal direction
- Box inertia transformed into world coordinates; impulses generate genuine torque and tumbling
- Translation-only split overlap correction; no collision impulse cache across steps and no sophisticated stack sleeping
- Quaternion spherical interpolation and linear position interpolation between surrounding fixed steps
- Small linear/angular damping, contact restitution threshold, overlap correction cap, and generous safety speed/spin limits

The collision geometry is the **box around each visible glyph**, including its hole; digits do not interlock through counters. Box mass distribution is uniform, not the real mass distribution of the glyph. The centered-mesh offset is accounted for. Face manifolds are approximate, and the solver is simpler than a mature rigid-body engine. Resting contacts may show minor jitter, and some overlap is possible during impact. No launch impulses, periodic artificial kicks, shuffled pose tables, or per-frame trajectory assignments are used.

## Replay, bounds and lifecycle

Physics is independent of requested frame rate and seek order. A seek reconstructs from a saved exact fixed-step state, never from an interpolated/rendered pose. At most 24 checkpoints are retained by default, with the initial checkpoint preserved; old seeks can require replay. Each checkpoint has the bounded set of bodies. The test verifies shuffled seeks, future-then-backward seeks, checkpoint eviction, and reset against exact serialized expected states in the same JS runtime. Different JS engines/hardware are not promised bit-identical floating-point results over long chaotic simulations.

A body is removed after its box center drops below -500, leaves lateral/depth safety bounds, reaches age 24 seconds, or exceeds the 96-body default emergency cap. Removal is checked each step, rather than only once per second as in the historical implementation. The reference demonstration uses a 48-body cap compatible with the renderer. The cap is a safety boundary; ordinary body counts are checked by the executable tests. Bodies below the view are culled rather than faded.

Birth/removal are discrete lifecycle events; surviving-body poses are smoothly interpolated. New births occur above the visible frame. A very old seek can be slower but does not grow cache memory indefinitely. Simulation duration is capped to bound pathological requests.

## Verification

Run `node motion-test.cjs`. The test module also exports `runTests()`.

Coverage includes browser/CommonJS loading, initial immediate fall, six-body cadence, fractional interpolation, minute/midnight rollover, seed repeatability and variation, exact replay/seek equality, non-finite and invalid inputs, glyph-specific dimensions, both fixed steps, bounded caches/lifecycle, and the calibrated preset.

Run the executable tests for current finite-state, replay and lifecycle observations. Stored example coordinates are deliberately omitted because changing geometry or any seed parameter changes chaotic trajectories. These are implementation checks, not claims of measured agreement with every source pose.
